## 你的任务

### Step 0: 文档健康检查（必须先做）

检查你的输入文档是否齐全：

| 文档 | 路径 | 缺失时行动 |
|------|------|-----------|
| PRD | docs/PRD-*.md | **必须先补**：读取代码，反推功能清单，编写 PRD 初稿 |
| 反馈分析 | docs/FEEDBACK-*.md | **必须先补**：收集用户反馈，编写反馈分析报告 |
| CHANGELOG | CHANGELOG.md | 读取了解已发布版本 |
| 现有代码 | 项目源码目录 | 读取代码了解现状 |

**如果 PRD 缺失：**
1. 读取项目代码，理解现有功能
2. 搜索 GitHub Issues、用户反馈了解需求
3. 编写 PRD 初稿到 docs/PRD-001-产品需求文档.md
4. 标注"初稿，待产品经理确认"
5. 继续迭代规划

**如果反馈分析缺失：**
1. 搜索 GitHub Issues、用户反馈
2. 搜索竞品动态、用户痛点
3. 编写反馈分析报告到 docs/FEEDBACK-001-反馈分析.md
4. 继续迭代规划

**文档健康检查完成后，确认：**
- [ ] PRD 存在且理解现有功能
- [ ] 反馈分析存在且理解用户需求
- [ ] 理解项目现状

### Step 1: 读取上下文

- docs/FEEDBACK-*.md（反馈分析报告）
- docs/PRD-*.md（现有 PRD）
- 项目代码结构和测试覆盖
- CHANGELOG.md（已发布版本）
- Git log（最近的变更）

### Step 2: 影响分析

对每个待改进项进行影响分析：

| 维度 | 评估内容 |
|------|----------|
| 代码影响 | 涉及哪些模块、文件 |
| 数据影响 | 是否需要 migration |
| API 影响 | 是否破坏现有 API |
| 测试影响 | 需要新增/修改哪些测试 |
| 文档影响 | 需要更新哪些文档 |
| 回归风险 | 可能影响哪些现有功能 |

### Step 3: 迭代计划

制定迭代计划，包含：

- **迭代目标：** 一句话描述本轮迭代的核心价值
- **功能清单：** 每项包含 ID、名称、优先级、预估工作量、验收标准
- **技术任务：** 重构、性能优化、技术债清理
- **风险和缓解：** 可能出问题的地方和应对方案
- **回滚方案：** 如果出问题怎么回退

### Step 4: 版本策略

- 语义化版本（major.minor.patch）
- Breaking change 必须升 major
- 新功能升 minor
- Bug 修复升 patch

### Step 5: 产出

迭代计划文档，参考 templates/iteration_template.md：
- docs/ITER-001-迭代计划.md
