## 智能并行调度

### 自动检测并行机会

分析 WORKFLOW_PLAN.md 中的依赖关系，自动识别可并行的 Agent：

```
依赖图：
编排总监（无依赖）
    ↓
市场分析师 ──────┐（无依赖，可并行）
产品经理 ←──────┘
    ↓
架构师（依赖 PRD 初稿）
    ↓
┌───────┬───────┬───────┬───────┐
开发     测试     运维     文档    （全部可并行）
└───────┴───────┴───────┘
    ↓
质量门禁（依赖所有执行完成）
```

### 并行执行规则

| 规则 | 说明 |
|------|------|
| 最大并行数 | 建议不超过 4 个 Agent 同时执行 |
| 依赖检查 | 启动前检查所有前置 Agent 是否完成 |
| 冲突检测 | 多个 Agent 写同一文件时，串行执行 |
| 进度追踪 | 每个 Agent 完成后更新 WORKFLOW_PLAN.md |

### 串行降级条件

以下情况必须串行执行：
- 架构师输出是开发的输入
- 测试依赖开发的代码
- 质量门禁依赖所有执行完成
- 用户明确要求串行

### 2. 模式选择

根据诊断结果选择模式：

**模式 A（从 0 到 1）：** 无现有代码或新 Phase

```
编排总监 → 市场分析师 + 产品经理 → 架构师 → 开发 + 测试 + 运维 + 文档 + 质量门禁 → 发布
```

**模式 B（持续迭代）：** 有现有代码和文档

```
需求侦察兵 + 反馈分析师 → 市场分析师 + 产品经理 → 迭代规划师 → 架构师 → 开发 + 测试 + 质量门禁 → 发布
```

**模式 C（长程恢复）：** 检测到 `docs/07-long-running/STATE.md` 存在

不重新跑前面已完成的 Agent，而是：

1. 读 `docs/07-long-running/STATE.md` 的「已完成 Agent 清单」+「下一步建议」
2. 直接定位到下一个 Agent 启动
3. 把 STATE.md 的「关键产出索引」列表传给下一个 Agent，避免重新扫码

```
resume.sh → 定位到「下一步建议」的 Agent → 单独启动该 Agent → 完成后更新 STATE.md
```

**单 Agent 触发模式**（高级）：用户也可以跳过 orchestrator，直接喊：

> 「我要补一份安全审计」→ 直接调用 `security-engineer`
> 「PRD 要改一下」→ 直接调用 `product-manager`

这种情况下，被触发的 Agent 仍然走 `Step 0` 读 STATE.md 恢复上下文，结束后更新 STATE.md。orchestrator 不参与。

## Agent 组合推荐

| 项目状态 | 推荐组合 | 理由 |

**快速决策：**
- 不确定用多少 Agent？从核心 4 个开始
- 时间紧迫？只用编排 + 开发
- 质量优先？用全部 20 个

## 错误处理

### Agent 执行失败

当某个 Agent 执行失败时：

1. **记录错误**：在 WORKFLOW_PLAN.md 中记录失败原因
2. **判断严重度**：
   - 阻塞：无法继续（如架构设计有根本缺陷）→ 回到上一步重新执行
   - 严重：可以继续但有风险（如测试覆盖不足）→ 标记后继续，下轮修复
   - 一般：不影响核心流程（如文档格式问题）→ 记录后继续
3. **重试策略**：
   - 同一 Agent 最多重试 2 次
   - 重试时提供上次的错误信息作为上下文
   - 2 次重试仍失败 → 降级处理（跳过或人工介入）

### 安全考虑
- 不在 WORKFLOW_PLAN.md 中记录密钥、密码、token
- Agent 产出物中的敏感信息必须脱敏
- 发现安全问题立即标记为阻塞

### 边缘案例

| 场景 | 处理方式 |
|------|----------|
| 项目完全空白（无代码无文档） | 从模式 A 开始，先让产品经理定义需求 |
| 项目只有代码无文档 | 让文档师先补文档，再继续 |
| Agent 输出为空 | 记录警告，跳过该 Agent，继续后续 |
| 多个 Agent 同时阻塞 | 降级为串行执行，逐个解决 |
| 用户中途修改需求 | 暂停当前流程，重新评估影响，更新 WORKFLOW_PLAN |
| 上下文窗口即将溢出 | 触发摘要压缩，只保留关键信息 |

### 上下文溢出

当 Agent 输出超过预算时：

1. 截断输出，保留关键部分
2. 在末尾添加"[已截断，完整内容见 docs/xxx.md]"
3. 下游 Agent 只读截断版本
