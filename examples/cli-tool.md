# Worked Example: CLI 工具（渐进式采用）

> 使用 product-lifecycle 最小可用集（4 个核心 Agent）构建一个命令行工具。
> 注：本例展示小项目如何用最少的 Agent 完成开发。

## 项目背景

- **项目名：** imgpress
- **描述：** 图片批量压缩 CLI 工具，支持 JPEG/PNG/WebP，保留 EXIF
- **技术栈：** Python + Pillow + Click
- **规模：** 预计 2-3 天完成，单人开发

## Agent 选择

编排总监检测到这是一个小型项目，决策树匹配「原型/MVP」级别：

- **编排总监** — 制定框架（必选）
- **开发工程师** — 代码实现（必选）
- **测试经理** — 测试验证（必选）
- **质量门禁** — 代码审查（必选）

**跳过的 Agent：** 市场分析师、产品经理、架构师、运维、文档、侦察兵、反馈分析师、迭代规划师。理由：CLI 工具功能明确，无需市场调研和架构设计。

## 执行过程

### Step 1: 框架制定（5 分钟）

**编排总监：**
- 读取项目描述，确认属于「原型/MVP」级别
- 生成 WORKFLOW_PLAN.md：4 个 Agent，单轮执行（无并行依赖）
- 跳过市场分析和架构设计，直接进入开发

### Step 2: 代码实现（30 分钟）

**开发工程师：**
- 读取 WORKFLOW_PLAN.md，确认需求：批量压缩、多格式、EXIF 保留
- 实现核心模块：
  - `cli.py` — Click 命令行入口（`imgpress compress --input ./photos --quality 80`）
  - `compressor.py` — 压缩引擎（JPEG 质量调整、PNG 优化、WebP 转换）
  - `exif.py` — EXIF 元数据保留
- 输出结构：`imgpress/` 包 + `setup.py`

### Step 3: 测试验证（15 分钟）

**测试经理：**
- 12 个测试用例：
  - 基本压缩（JPEG 80% 质量 → 文件体积减少 60%+）
  - 多格式支持（PNG → WebP 转换）
  - EXIF 保留验证（压缩后 EXIF 数据完整）
  - 边界情况（空目录、损坏图片、超大文件）
- 结果：12/12 通过

### Step 4: 代码审查（10 分钟）

**质量门禁：**
- 发现：`compressor.py` 中 PNG 压缩未处理透明通道
- 建议：添加 `--preserve-alpha` 参数
- 开发工程师修复后通过审查
- 附加建议：添加 `--verbose` 模式显示压缩进度

## 产出物清单

| 文件 | 说明 |
|------|------|
| WORKFLOW_PLAN.md | 编排总监的工作流计划 |
| imgpress/cli.py | CLI 入口 |
| imgpress/compressor.py | 压缩引擎 |
| imgpress/exif.py | EXIF 处理 |
| tests/test_compressor.py | 12 个测试用例 |
| setup.py | 包安装配置 |

## 总耗时

```
00:00  编排总监（5 分钟）
00:05  开发工程师（30 分钟）
00:35  测试经理（15 分钟）
00:50  质量门禁（10 分钟）
01:00  完成
```

## 关键经验

1. **4 个 Agent 足够**：功能明确的小项目不需要市场分析和架构设计
2. **质量门禁仍有价值**：即使小项目，代码审查也能发现透明通道处理遗漏
3. **总耗时 1 小时**：比全流程（12 Agent）节省约 60% 时间
