常见问题（FAQ）

安装、模式选择、断流与工具数等高频问题。权威 Markdown：docs/01-getting-started/FAQ.md。

使用相关

我只想用 1 个 Agent，可以吗？

可以。直接 Read agents/xxx.md 并按指引执行，或在 /pl 选 C 单角色。

小项目也要 20 个 Agent 吗？

不需要。最小集：编排总监、开发工程师、测试经理、质量门禁（4 个）。见 docs/01-getting-started/DECISION-TREE.md。

/pl 没反应或 unrecognized？

确认 ~/.claude/skills/pl/SKILL.md 存在（顶层 pl 目录，不是只在 product-lifecycle 包内嵌路径）。安装后需新开 session。

编排总监为什么变成子 Agent？

设计上是：主会话读 SKILL.md 扮演编排总监，再派发其他 19 个角色。不应把 orchestrator 当普通子代理自动触发（v3.4+ 已修正 description 与 SUBAGENT_GUARD）。

模式与流程

模式 A 和 B 有什么区别？

A：0→1，完整调研与架构。B：已有产品，侦察/反馈驱动增量迭代。

Agent 之间如何传递信息？

通过 docs/ 下结构化文档；下游优先读摘要与 WORKFLOW_PLAN，按需读全文。

技术与故障

为什么有 149 个 tools？

常见原因：项目 .mcp.json 挂了 mysql-mcp-server（约 99 tool）+ 20 agent + 内置工具。从业务项目移除未用的 MCP，全局 ~/.claude/settings.json 的 mcpServers 保持空。

peer closed connection / incomplete chunked read？

多为上游中转在流式响应中超时（大上下文 ~8 万 token + 多 tool）。缓解：/compact、精简模式、减少 MCP、大上下文换长上下文模型路由。

还要单独装 superpowers-zh 吗？

不需要。方法论 skill 已内置在 product-lifecycle/skills/。
