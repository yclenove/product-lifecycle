5.1 为什么 AI 需要流程

单次对话能写代码，但做产品需要顺序、门禁、可追溯产出。流程不是 bureaucracy，而是对抗幻觉、遗忘和上下文爆炸的手段。

没有流程时会发生什么

  • 跳步：没 PRD 就写库表，后期返工
  • 幻觉：编造不存在的 API、竞品数据
  • 失忆：新 session 不知道上一轮定了什么
  • 膨胀：同一文件被反复全文读取，token 暴涨

流程在本项目里是什么

不是瀑布文档堆砌，而是：

  1. 角色分工：每个 Agent 只做一类事（产品不写代码、开发不擅自改需求）
  2. 文档传递：下游读上游产出（PRD → 架构 → 开发）
  3. 质量门禁：测试/审查不通过则回环
  4. 可恢复状态：长程模式下 STATE.md 记录进度

与「一个超强 prompt」的对比

方式优点缺点
单 prompt 包办启动快难维护、难并行、难审计
多 Agent + 流程可裁剪、可复用、产出结构化需要学习编排与目录约定
