6.3 团队协作工作流

多人时，用 Git + 结构化 docs/ + WORKFLOW_PLAN 分工，编排总监负责阶段与门禁，避免多人改同一份 PRD 冲突。

推荐分工

真人角色对应 Agent产出
产品负责人产品经理 / 迭代规划师PRD、迭代计划
技术负责人架构师 / DBAARCH、数据模型
开发前端 / 后端 / 开发工程师代码 + DEV 文档
QA测试经理 / 质量门禁QA 报告、门禁结论
项目经理项目经理 / 编排总监排期、风险、WORKFLOW_PLAN

Git 约定

  • docs/iterations/current/：当前迭代，可频繁提交
  • docs/07-long-running/STATE.md：可个人 gitignore，或团队共管需约定 merge 规则
  • CHECKPOINTS/：建议进库，作为里程碑
  • 迭代结束：归档到 docs/iterations/archive/ 或历史目录

沟通

Agent 间不传私聊，只传文档。评审在 PR 里对 docs/iterations/current/product/PRD-*.md 评论，AI 下一轮读取最新版继续。

见 docs/03-workflow/AGENT-COMMUNICATION.md
