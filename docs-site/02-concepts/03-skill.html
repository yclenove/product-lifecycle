2.3 Skill 是什么

Agent 解决"我是谁、我干啥"，Skill 解决"我用什么方法干"。 本文讲 skill 在本项目里的具体形态、跟 Agent 的关系、怎么集成 superpowers-zh 的 20+ 通用 skill。

类比解释

用一个真实公司的类比：

公司里的本项目里的
员工 = 张三（后端工程师）Agent = backend-developer
方法论 = 张三学过的 TDD、DDD、设计模式Skill = TDD skill、DDD skill、debugging skill
张三用 TDD 写代码backend Agent 引用 TDD skill 写代码

Skill 不绑定到具体某个 Agent，它是共享的工作方法。 后端要用 TDD，前端也可以用，QA 也可以用。

Skill 长什么样

Skill 是一个文件夹，里面至少有一个 SKILL.md：

~/.claude/skills/
├── test-driven-development/
│   └── SKILL.md
├── systematic-debugging/
│   └── SKILL.md
├── brainstorming/
│   └── SKILL.md
└── ...

SKILL.md 内部结构例如 TDD：

---
description: 在实现任何功能或修复 bug 时使用，先写测试再写实现
---

# Test-Driven Development

## 核心原则
1. Red：先写失败的测试
2. Green：写最简代码让测试通过
3. Refactor：在测试保护下重构

## 工作步骤
1. 阅读需求 / bug 描述
2. 列出可观察的行为
3. 为每个行为写测试用例
4. ...

## 反模式
❌ 先写代码再补测试
❌ 写完整功能再开始测试
...

Agent 怎么"用"skill

有两种方式：

方式 1：声明式引用

在 Agent prompt 里写：

## 推荐方法论 skills
- test-driven-development
- systematic-debugging
- chinese-documentation

Claude Code 看到这段，会主动建议或读取对应的 SKILL.md，让 AI 在干活前先了解方法。

方式 2：动态触发

某些 skill 在 SKILL.md frontmatter 里写了"何时触发"。

---
description: 在实现任何功能或修复 bug 时使用 ← 这里写触发条件
---

Claude Code 看到符合条件的请求会主动启用。

本项目集成了哪些 skill

本项目从 superpowers-zh 集成了 20+ 个通用 skill。

开发/调试类

  • test-driven-development：TDD
  • systematic-debugging：系统化调试
  • verification-before-completion：交付前自验证
  • receiving-code-review：怎么应对 code review
  • requesting-code-review：怎么请求 code review

设计 / 计划类

  • brainstorming：动手前先穷举可能性
  • writing-plans：把任务写成可执行计划
  • executing-plans：分步执行已有计划
  • subagent-driven-development：派发子任务给其他 Agent

协作 / 流程类

  • dispatching-parallel-agents：并行调度多个 Agent
  • using-git-worktrees：用 git worktree 隔离并行工作
  • finishing-a-development-branch：分支收尾

中文本地化

  • chinese-documentation：中文文档排版（中英文空格、术语）
  • chinese-commit-conventions：中文 commit 规范
  • chinese-code-review：中文 review 沟通
  • chinese-git-workflow：国内 Git 平台适配

工具构建类

  • mcp-builder：写 MCP 服务器
  • writing-skills：怎么写一个新 skill
  • workflow-runner：跑 YAML 工作流

怎么安装 skill

方式 A：一行命令（推荐）

npx superpowers-zh

自动下载所有 superpowers-zh skill 到 ~/.claude/skills/。

方式 B：本项目的脚本

bash scripts/install-skills.sh

或 Windows：

powershell -File scripts/install-skills.ps1

方式 C：手动 clone

git clone https://github.com/jnMetaCode/superpowers-zh.git ~/.claude/skills/superpowers-zh

卸载

npx superpowers-zh --uninstall
# 或
bash scripts/install-skills.sh --uninstall

Skill vs Agent 的边界

问题用 Agent用 Skill
有一个稳定的角色身份吗 ✅ 是（架构师 / QA …） ❌
是一种通用工作方法 ❌ ✅（TDD / 调试 …）
会被多个角色复用 不 会
产出固定格式文档 是（按模板） 不一定

自己写一个 skill

非常简单：

mkdir -p ~/.claude/skills/my-skill
cat > ~/.claude/skills/my-skill/SKILL.md <<'EOF'
---
description: 描述什么时候应该用这个 skill
---

# 我的 skill

## 核心原则
...

## 工作步骤
1. ...
2. ...

## 反模式
❌ ...
EOF

下次 Claude Code 启动就能看到。

⚡ 进阶：Skill 的本质是文档

你可能会问：skill 就只是一个 markdown 文件？没有代码、没有插件、没有运行时？ —— 是的。

这是 Anthropic Skills 的设计哲学： 让 AI 学习"怎么干"的最直接方式不是写代码插件，而是给它一份"工作手册"。 AI 模型有理解人类文档的能力，所以一份好文档 ≈ 一个好"插件"。

这跟 ChatGPT 早期的 "Custom Instructions" 是同一思路，只是更结构化。
