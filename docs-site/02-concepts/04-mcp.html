2.4 MCP 协议入门

MCP（Model Context Protocol）是 Anthropic 推出的"AI 调外部工具"协议。 本项目用它集成了 drawio MCP——让 AI 直接画 draw.io 流程图。 本文讲清 MCP 是什么、解决什么问题、本项目怎么用、自己怎么装更多 MCP。

先看一个直观例子

没装 MCP 之前，你跟 Claude 说"画一个用户登录的时序图"，它给你的是：

  • 一段 Mermaid 代码（你要复制粘贴到 mermaid.live 或某个支持的工具）
  • 或者 ASCII 图（"丑"，难看）
  • 或者文字描述（"用户输入 → 前端 → 后端 → 数据库..."）

装了 drawio MCP 之后：

Claude 直接调用 MCP 工具，生成一个 .drawio 文件 + 渲染好的 SVG，存到你指定目录。 你打开就是漂亮的 draw.io 图，可以继续手工编辑。

类比理解

把 AI 模型比作大脑。

  • 没有工具 = 一个只会说话的大脑，啥也干不了
  • 内置工具（Read/Edit/Bash） = 大脑长了眼睛、手、嘴（限于 IDE 内部）
  • MCP 工具 = 大脑可以"打电话"给外部的专业服务（drawio 服务、数据库服务、邮件服务…）

MCP 全称解释

Model Context Protocol

  • Model：指 LLM（Claude 等）
  • Context：上下文。这里指"模型干活需要的额外能力 / 数据"
  • Protocol：协议。定义了"模型怎么发请求、外部工具怎么回应"

所以 MCP 是 让模型获取额外能力的标准化协议。

为什么需要"协议"？

没有协议之前的混乱：

  • OpenAI 有"function calling"格式
  • Claude 有自己的"tool use"格式
  • 每个工具开发者写一次，要适配 3-5 个 AI 厂商

有了 MCP 之后：

  • 工具只要实现 MCP 协议（一份代码）
  • 任何支持 MCP 的客户端（Claude Desktop、Claude Code、Cursor）都能用
  • 就像 USB —— 一个标准，所有设备插上就能用

MCP 客户端 / 服务器

MCP 是 client-server 架构：

  • MCP Client：AI 工具，比如 Claude Code、Cursor
  • MCP Server：提供工具能力的外部程序，比如 drawio MCP

两者通过标准输入输出（stdio）或 SSE 通信，传 JSON-RPC 消息。

本项目集成的 MCP

drawio MCP

来自 DayuanJiang/next-ai-draw-io， 让 AI 能生成 drawio 流程图。

能画什么

  • 流程图（Flowchart）
  • 时序图（Sequence Diagram）
  • 状态图（State Diagram）
  • 类图 / ER 图（Entity Relationship）
  • 系统架构图
  • 组织结构图
  • 泳道图
  • 更多 …

怎么调用（在 Claude Code 里）

请帮我画一个用户注册的时序图，
角色：用户、前端、API网关、用户服务、邮件服务
存到 docs/iterations/current/diagrams/seq-register.svg
请用 drawio MCP

Claude 会调用 MCP，生成 SVG。

本项目的 MCP 配置

项目根目录有 .mcp.json（Claude Desktop 用）和 .cursor/mcp.json（Cursor 用）：

{
  "mcpServers": {
    "drawio": {
      "command": "npx",
      "args": ["-y", "next-ai-draw-io"]
    }
  }
}

意思是："启动一个名为 drawio 的 MCP server，通过 npx 运行 next-ai-draw-io 包"。

怎么装

方式 1：用本项目的安装脚本（推荐）

bash scripts/install-mcp.sh
# 或 Windows
powershell -File scripts/install-mcp.ps1

脚本会注册到 Claude Code 全局配置。

方式 2：手动注册（Claude Code）

claude mcp add drawio "npx -y next-ai-draw-io"

方式 3：项目级（推荐用方式 1，已自动配好）

项目里有 .mcp.json，Claude Code 在该目录启动时会读取。

验证安装

claude mcp list

应该能看到 drawio 在列表里。

或在 Claude Code 里问：

你能用 drawio MCP 吗？

它应该回复"能"，并能开始画。

本项目怎么让 AI 主动用 drawio MCP

三处机制：

  1. Agent prompt：每个角色的 prompt 里有"应该画的图"章节，注明优先用 drawio MCP
  2. 模板：每个文档模板首部有"图示要求"，要求该文档必含哪些图
  3. CI 检查：scripts/check-diagrams.sh 会检查迭代产出中是否包含必要的图

更多 MCP（社区生态）

除了 drawio，还有大量社区 MCP，可以按需装：

MCP能力
github读 issue、PR、代码
postgres / mysql查数据库
slack读写 Slack 消息
filesystem更细粒度的文件操作
memory给 AI 配长期记忆
puppeteer操控浏览器
fetch访问 URL

官方仓库：modelcontextprotocol/servers

注意事项

⚠️ MCP 安全提醒
  • MCP server 是外部程序，能访问你的文件和网络。装之前确认来源可信
  • 给 AI 配的 MCP 工具会消耗 token（每次调用都要传协议消息）
  • 调慢的 MCP（比如复杂渲染）会让对话卡顿
  • 失败时 AI 会给文字描述兜底（比如 Mermaid 代码）
⚡ 进阶：MCP 与 Function Calling 的区别

Function Calling（OpenAI、Claude 都有）是模型 API 的能力—— 模型可以返回"我想调用 funcX(arg1, arg2)"，由调用方实际执行。

MCP 是更上层的协议—— 它标准化了工具描述、调用、返回的格式，使得：

  • 工具开发者写一份代码适配所有 AI 厂商
  • 工具可以被远程托管（不一定本地）
  • 工具发现、权限、生命周期都标准化

实际实现上，MCP server 把工具列表给 client，client 通过 LLM 的 function calling 让模型选择， 选完后 client 通过 MCP 协议调 server 执行。
