2.2 Prompt 与模板

Agent 是 "灵魂"，模板是 "骨架"。本文讲两者关系、为什么本项目两个都要、怎么自己写一个好 prompt。

Prompt 是什么

Prompt = 你跟 AI 说的话。但"专业 prompt"跟"日常对话"差别巨大。

糟糕的 prompt

帮我写个登录功能

AI 给你的：随便写一段 React + Express 代码，可能用 JWT，可能用 Session，可能没考虑安全，可能漏了忘记密码。

专业的 prompt

你是一个后端工程师。请基于下面的 PRD 实现登录接口。

要求：
1. 使用我们项目已有的 PostgreSQL + Node.js + Express
2. 密码必须 bcrypt 加盐哈希
3. 登录返回 JWT，过期时间 7 天
4. 错误码遵循 RFC 7807 格式
5. 必须写 Jest 单测，覆盖率不低于 80%
6. 接口文档用 OpenAPI 3.0 格式输出

参考资料：
- 我们的项目结构：[贴 tree]
- 现有的用户表：[贴 SQL]
- 错误处理中间件：[贴代码]

请按以下步骤工作：
1. 先列出实现计划（不写代码）
2. 等我确认后再开始
3. 完成后给我自测清单

AI 给你的：结构清晰、规范、可用的代码，附自测清单。

专业 prompt 的 7 要素

要素作用示例
① 身份设定切换 AI 思维模式"你是后端工程师"
② 任务目标明确干什么"实现登录接口"
③ 上下文背景信息项目结构、现有代码
④ 约束条件必须遵守的规则用 bcrypt、JWT 7 天
⑤ 工作步骤分阶段指引"先列计划，等确认"
⑥ 产出格式要交付什么代码 + OpenAPI + 自测清单
⑦ 异常处理遇到不确定怎么办"不清楚的地方先问我"

本项目的每个 Agent prompt 都是按这 7 要素写的。

什么是模板

Prompt 是给 AI 看的"操作说明"。模板是给 AI 看的"产出格式"。

本项目 templates/ 目录下有 20+ 个模板。打开 templates/product_template.md：

# PRD-{编号}-{产品名}-{版本}

## 图示要求
[本类型文档必须包含的图]

## 1. 背景与目标
- 业务背景：
- 北极星指标：
- 成功标准：

## 2. 用户画像
| 画像 | 描述 | 关键诉求 |
|------|------|---------|
| ...  | ...  | ...     |

## 3. 用户故事
- US-001：作为 [X]，我想 [Y]，以便 [Z]
- US-002：...

## 4. 功能列表
| ID | 功能 | 优先级 | 验收标准 |
|----|------|--------|---------|
| F-01 | ... | P0     | ...     |

## 5. 用户旅程图
[用 drawio MCP 或 Mermaid 画]

## 6. 非功能需求
- 性能：
- 安全：
- 可访问性：

## 7. 验收清单
- [ ] 所有 P0 功能都有验收标准
- [ ] 关键路径有用户旅程图
- [ ] 与上版 PRD 的 diff 已说明

这就是 PRD 模板。产品经理 Agent 看到它就知道"PRD 该长这样"，按节填即可。

Prompt + 模板的协同

具体流程：

  1. 编排总监说"调用产品经理 Agent"
  2. Claude 读取 agents/product-manager.md（这是 prompt）
  3. Prompt 告诉它"写 PRD 时按 templates/product_template.md"
  4. Claude 读取模板，看到所有章节、表格、必含内容
  5. Claude 填空式产出，存到 docs/iterations/current/PRD-001.md

为什么不把模板直接塞进 prompt？

可以，但分开有好处：

  • 可复用：一个模板可被多个 Agent 引用（QA 角色也会引用 PRD 模板做对照）
  • 可独立演进：模板改了不用动 prompt，反之亦然
  • 可被人编辑：模板是"半成品"，人可以直接拿去填
  • 可被工具校验：CI 脚本可以检查"是否所有章节都填了"

本项目 prompt 的特色设计

① 强制 Step 0：恢复上下文

每个 Agent 第一步是检查 docs/07-long-running/STATE.md。 没有就跳过；有就先复盘上次干到哪了。

## Step 0：恢复上下文（长程迭代模式）
1. 检查 docs/07-long-running/STATE.md 是否存在
2. 如果存在，读取并复述：
   - 当前迭代 ID
   - 上次完成到哪一步
   - 待办事项
   - 已知阻塞
3. 如果不存在，跳过此步

② 强制画图要求

每个 Agent 都明确"你必须画哪些图"。比如产品经理：

## 应该画的图
- 用户旅程图（mandatory）
- 用户故事地图（recommended）
- 信息架构图（recommended）

优先使用 drawio MCP；如不可用，退回 Mermaid。
图存放路径：docs/iterations/current/diagrams/

③ 推荐 skills

每个角色推荐方法论 skill，AI 会读 skill 文件，获取该方法论的细节。

## 推荐方法论 skills
- brainstorming：写 PRD 前用它探索用户意图
- chinese-documentation：保证文档排版规范

④ 产出契约

所有 Agent 都明确"我做完会输出哪个文件"，方便编排总监知道下一个角色能读什么。

## 产出物
- 路径：docs/iterations/current/PRD-XXX-{产品名}-{版本}.md
- 必含章节：背景 / 用户故事 / 功能列表 / 用户旅程图 / 验收清单

自己写一个好 prompt 的清单

✅ 检查清单
  1. 有没有清晰的身份设定？
  2. 任务目标是不是一句话能说清？
  3. 给了足够上下文吗？（项目结构、现有代码）
  4. 约束条件具体吗？（技术栈、规范、性能要求）
  5. 有分步骤吗？（避免一口气吐 5000 字）
  6. 产出格式约定了吗？（markdown / 代码 / OpenAPI…）
  7. 失败兜底说了吗？（不会的时候是问你还是猜？）

常见错误

❌ 错误 1：让 AI "自由发挥"

"你帮我设计一个用户体验" — AI 会按自己理解的"通用最佳实践"做，跟你业务无关。
应改为："基于以下用户画像和功能列表，设计登录流程的 UI。要考虑 [具体场景]。"

❌ 错误 2：一口气给 10 个任务

"帮我做需求 + 架构 + 代码 + 测试 + 部署" — AI 会每个都浅尝辄止。
应改为：分 5 次调用 5 个角色。或者只让它做一件事，做深。

❌ 错误 3：没给上下文就让它继续

"在我的项目里加 OAuth 登录" — 你的项目用什么语言、什么框架它根本不知道。
应改为：先 cat package.json 让 AI 看一遍，或者贴关键文件。
