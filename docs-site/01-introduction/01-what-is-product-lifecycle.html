product-lifecycle 是什么

它是一套让 AI 像产品团队一样工作的"流程框架 + 角色提示词 + 模板 + 自动化"组合包。 本文从最朴素的疑问讲起，30 秒说清核心思想，5 分钟知道值不值得学。

📍 适合谁读 完全没接触过这个项目的人、或者听过名字但不知道具体是什么的人。

🤔 你可能有的疑问

  • "我已经在用 Claude Code / Cursor 写代码了，为什么还需要这玩意？"
  • "20 个角色不会太麻烦吗？我做小项目用得着这么重？"
  • "这是一个 IDE 插件？一个网站？一个程序？"
  • "我得装 Python / Node / Docker 什么的吗？"
  • "和 GPT、Claude 这些 AI 助手是什么关系？"

一句话回答

它是一个 文件夹。里面装了 20 份针对不同角色（产品经理、架构师、QA…） 写好的 AI 提示词（prompt），加上文档模板、画图规范、自动化脚本。 把它放到你的项目目录或 AI 工具的"技能"目录里，AI 就知道"产品该这么做"。

解释每个生僻词

prompt（提示词）

你跟 AI 说的话。比如你跟 ChatGPT 说"帮我写一首诗"， "帮我写一首诗"就是 prompt。专业的 prompt 长得多，可能 500-2000 字， 包含身份设定、任务步骤、产出格式、注意事项。

本项目的 20 个角色，每个就是一份精心写好的长 prompt。

Agent（智能体 / 角色）

在本项目里，Agent ≈ "扮演特定角色的 AI"。 它本质就是"AI + 一份专门的 prompt"。 例如架构师 Agent = Claude + 一份让它扮演架构师的 prompt。

编排（Orchestration）

决定"谁先干、谁后干、谁可以并行"。 做产品不可能 20 个角色一起冲，要有顺序： 先市场分析 → 然后产品经理写 PRD → 然后架构师设计 → 然后开发…… 编排总监这个 Agent 专门负责调度。

迭代（Iteration）

软件不是一次性做完的，要分版本（v1.0 → v1.1 → v2.0）。 每个版本叫一次迭代。本项目支持"做完一轮归档，开始下一轮"的工作模式。

MCP（Model Context Protocol）

Anthropic 推出的协议，让 AI 助手能调外部工具。 本项目集成了 drawio MCP，让 AI 能画 draw.io 流程图。 详见 2.4 MCP 协议入门。

跟你已经在用的东西的关系

你已经在用product-lifecycle 给你加了什么
Claude Code / Cursor 让它从"通用代码助手"变成"产品团队"，覆盖代码之外的产品全流程
ChatGPT / Claude.ai 网页版 把零散的对话变成结构化产出（PRD、架构文档、测试计划等都有模板）
Notion / 飞书文档 这俩是"放文档"的地方，本项目是"AI 帮你写文档"的方法
Jira / 禅道 不替代项目管理，但能让 AI 帮你输出任务拆解、排期、风险登记
Mermaid / draw.io / PPT 本项目集成了 drawio MCP，AI 直接画图；不喜欢可以让它生成 Mermaid

它不是什么

避免误解，先排除：

  • ❌ 不是一个 AI 模型。它不"懂"什么，它只是教 Claude/GPT 该怎么干。
  • ❌ 不是一个 IDE。你还是在 Cursor / Claude Code / VS Code 里写代码。
  • ❌ 不是一个 SaaS。完全离线，文件都在你电脑上。
  • ❌ 不是代替你做决策。是给你"产品流程的脚手架"，最后拍板的还是你。
  • ❌ 不是"无脑生成代码"。每个角色都强调先理解需求、再做方案、再写代码。

真实工作流长啥样

假设你说"我想做一个团队任务管理工具"。打开 Claude Code，输入：

/product-lifecycle taskhub "团队任务管理工具，类似 Asana 但更轻"

会按以下顺序运行（你能看到每一步）：

  1. 编排总监诊断：项目无代码、无文档 → 启动模式 A（从 0 到 1）
  2. 市场分析师：搜竞品（Asana / Trello / Linear / 飞书项目）→ 写市场分析报告
  3. 产品经理：基于市场分析，写 PRD（含用户故事、功能优先级）
  4. UI/UX 设计师：信息架构图、关键页面线框图
  5. 架构师：技术选型（React + Node + PostgreSQL？）、画系统架构图
  6. 后端工程师：API 设计、时序图、数据库表设计
  7. 前端工程师：组件树、状态机
  8. 测试经理：测试计划、用例脑图
  9. 质量门禁：检查每个产出物是否合格

每个角色 5-20 分钟，最后你拿到一套完整的产品规划文档 + 可以让 AI 开始写代码的清晰路径。 关键：所有产出都存成 markdown 文档，可以在 git 里版本管理、人工 review、修改后再让 AI 继续。

什么时候不用它

  • 只是改 1 个 bug → 用 Claude Code / Cursor 直接改就行
  • 玩具脚本（10 行解决） → 不用
  • 已经有非常详细的设计文档，只是要 AI 实现 → 直接调 developer 这一个角色就够
  • 你的项目极简单，3 天就能做完，不需要这么多文档层次

判断标准："项目超过 1 周 + 涉及多个模块 + 别人也要参与" 就值得用。
