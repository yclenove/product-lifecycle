为什么要 20 个 Agent

很多人第一反应是："弄这么多角色不复杂吗？一个 AI 一个 prompt 不行吗？" 本文用最直白的方式说清「分角色」相比「单 prompt 包打天下」好在哪。

先看反例：单 prompt 包打天下

假设你跟 Claude 说：

"你是一个全能的产品研发专家。请帮我做一个团队任务管理工具，包含市场分析、产品需求、架构设计、前后端代码、测试用例、部署方案。"

会发生什么？

  1. 它会一口气吐出几千字，但每一段都比较敷衍，因为 AI 在试图覆盖太多领域
  2. 市场分析会很泛（"市场需求广阔，竞品有 A、B、C"），没有具体数据
  3. 架构会写得像教科书（"采用 MVC 分层"），但跟你的业务不贴合
  4. 前后端代码会写一半，剩下的写"// TODO"
  5. 它不会主动质疑你的需求，因为没有"产品经理 vs 工程师"的角色对立

本质问题：AI 的注意力是有限的。一次承担太多职责，每个都做不深。

分角色 = 分注意力

人类公司为什么分部门？因为一个人当不了产品经理同时又当架构师同时又当 QA。 AI 也一样：每次只让它做一件事，做深、做透。

当你说"调用产品经理 Agent"时，AI 的注意力被聚焦到：

  • 关心用户故事，不关心技术细节
  • 关心需求优先级，不关心怎么实现
  • 关心 PRD 模板的每个章节是否填全
  • 关心要不要去搜竞品（产品经理 prompt 里明确要求 WebSearch）

它脑子里只装这些事，自然做得好。

第二个好处：可追溯的产出物

分角色还有一个工程上的好处：每个角色的产出是具体的文件，不是聊天记录。

  • 市场分析师 → MKT-001-市场分析报告.md
  • 产品经理 → PRD-001-产品需求.md
  • 架构师 → ARCH-001-技术设计.md
  • 测试经理 → QA-001-测试计划.md

好处：

  • 可以人工 review，发现问题让 AI 重做
  • 可以 git 版本管理，看变化
  • 下次迭代时，新的 Agent 能读到上一轮的产出
  • 团队成员可以查阅，不只是 AI 自己知道

第三个好处：质量门禁

每个角色的产出物都有"验收标准"。例如 PRD 的门禁：

  • ✅ 是否有用户故事
  • ✅ 是否有功能优先级（P0/P1/P2）
  • ✅ 是否有用户旅程图
  • ✅ 是否有验收标准

单 prompt 包打天下做不到这个 —— 它哪有空检查自己。 本项目有"质量门禁 Agent"专门做检查。

为什么具体是 20 个？

不是拍脑袋，是按照实际研发链路拆出来的：

规划层（4 个）

角色职责
编排总监总调度
项目经理（PMO）排期、风险
需求侦察兵主动扫描市场和体检产品
迭代规划师把需求切成版本

研究层（4 个）

角色职责
市场分析师竞品、用户痛点
反馈分析师用户反馈收集分类
数据分析师指标、AB 实验
产品经理PRD、用户故事

设计层（3 个）

角色职责
UI/UX 设计师用户旅程、线框、设计系统
架构师系统设计
DBA数据库设计

开发层（3 个）

角色职责
开发工程师（通用）小项目用
前端工程师组件、状态、性能
后端工程师API、领域、数据访问

质量层（4 个）

角色职责
测试经理测试计划、用例
代码审查员代码 review
安全工程师威胁建模、安全审计
质量门禁最后把关

运维 + 文档（2 个）

角色职责
运维工程师部署、CI/CD
技术文档师README、CHANGELOG、API doc

4+4+3+3+4+2 = 20。覆盖一个产品从想法到上线的完整闭环。

"我做小项目，用得着 20 个吗？"

不用。本项目支持"按需挑选"：

场景推荐角色组合
1 天小项目编排 + 开发（2 个）
1 周小工具编排 + 产品 + 开发 + 测试（4 个）
1 个月正经产品核心 8 个
大型企业项目全部 20 个 + 项目经理

详见 决策树。

真的多角色就好吗？也有代价

⚠️ 多角色的代价
  • 慢：跑完 20 个角色比单 prompt 慢 5-10 倍
  • 贵：每个角色都消耗 token，总 token 量大
  • 需要管理：产出文档变多，要会 git、会归档
  • 不适合即兴：玩 demo 不该用这个

所以本项目强调：按项目规模选角色子集。不是说必须 20 个一起上。

更深的设计哲学

⚡ 进阶：Agent 设计的两个流派

当前 Agent 体系有两大思路：

  1. Autonomy 派（AutoGPT、BabyAGI）：让一个 AI 自由规划+执行，最少人工介入。优点是省事，缺点是经常跑偏
  2. Structured 派（本项目、LangChain 的 chains）：用流程、模板、检查点把 AI 约束在合理路径上

本项目属于 Structured 派 —— 我们认为当前阶段的 AI 还不够稳定，给定结构反而能产出更好结果。 随着模型能力提升，这两派会逐渐融合。

想深入这个话题，读 Anthropic 的 Building effective agents。
