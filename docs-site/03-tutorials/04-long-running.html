3.4 长程跨天迭代

项目跨多天、多 session 时，用 STATE.md + checkpoint + handoff 让 AI 不用每次从头读完全部历史。

何时需要长程模式？

  • 项目周期超过 3 天
  • 单 session 上下文接近模型上限
  • 经常换机器或关窗口续做
  • 多人交接同一条迭代线

半天内能做完的小任务不必启用，避免过度工程。

三件套

文件作用
docs/07-long-running/STATE.md心跳：已完成 Agent、阻塞项、下一步
docs/07-long-running/HANDOFF.mdsession 结束前的移交单
docs/07-long-running/CHECKPOINTS/阶段里程碑快照（PRD/架构/QA 等）

启用

# 在业务项目根目录
cp docs/07-long-running/STATE.template.md docs/07-long-running/STATE.md
# 编辑 STATE.md 填写当前迭代与阶段

存在 STATE.md 后，各 Agent 的 Step 0 会自动读取并更新（子代理被编排器调用时可跳过，见 v3.4 优化说明）。

常用命令

# 新 session 恢复上下文
bash scripts/resume.sh

# 阶段完成打检查点
bash scripts/checkpoint.sh product-manager "PRD v1 定稿"

# session 结束前生成交移交单
bash scripts/handoff.sh

SessionStart 自动注入

技能包 hooks/session-start.sh 会在 Claude Code 新会话启动时，把 STATE.md 摘要注入上下文（若文件存在）。

与 iterations 目录的区别 07-long-running/ 是进行中状态；docs/iterations/ 归档已结束迭代的产物。

仓库权威说明：docs/07-long-running/README.md
