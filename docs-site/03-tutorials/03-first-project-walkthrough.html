3.3 第一个项目完整走读

用「精简模式」跑通一次：编排 → 产品 → 架构 → 开发 → 测试，产出落在业务仓库的 docs/ 里。

📍 假设 你有一个空目录或半成品 Web 应用，想用 product-lifecycle 从需求写到可运行代码。全程约 30–60 分钟（视模型与网络而定）。

第 0 步：准备业务仓库

mkdir my-saas-demo && cd my-saas-demo
git init
mkdir docs docs/iterations/current

第 1 步：启动编排（Claude Code 示例）

cd my-saas-demo
claude
> /pl my-saas-demo "团队任务管理 SaaS，支持看板与提醒"

在 Phase 0 确认里选 B 精简模式，指定角色：编排总监、产品经理、架构师、开发工程师、测试经理。

第 2 步：各角色产出（建议顺序）

顺序角色典型产出路径
1编排总监docs/WORKFLOW_PLAN.md 或 docs/iterations/current/...
2产品经理docs/iterations/current/product/PRD-*.md
3架构师docs/iterations/current/architecture/ARCH-*.md
4开发工程师代码 + docs/iterations/current/dev/DEV-*.md
5测试经理docs/iterations/current/qa/QA-*.md

第 3 步：检查门禁

  • PRD 是否包含用户故事与验收标准？
  • 架构是否覆盖数据模型与 API 边界？
  • 代码是否可 npm test / go test 通过？

可选：让质量门禁做最后一轮审查。

常见踩坑

  • 在技能包目录里跑 /pl：应在业务项目根目录打开 Claude Code，产出才进业务 docs/。
  • 一次选全量 20 Agent：上下文会暴涨，中转易断流；新手务必用精简模式。
  • 未替换占位符：各 agents/*.md 里的 {{PROJECT_NAME}} 需换成真实项目名。
