## 五、技术方案概要

### 5.1 Agent 数量全局修正（F01）

**方案：** 使用 sed/grep 批量替换，配合 validate.sh 残留检查

**涉及文件：**
- SKILL.md（3 处）
- README.md（2 处）
- orchestrator.md（2 处）
- .claude/agents/orchestrator.md（2 处）
- SKILL-CURSOR.md（7 处）

**替换规则：**
- `12 个 Agent` → `14 个 Agent`
- `13 个 Agent` → `14 个 Agent`
- `12 角色` → `14 角色`
- `13 角色` → `14 角色`

### 5.2 SKILL-CLAUDE-CODE.md Subagent 表补全（F02）

**方案：** 在现有 12 行表格末尾增加 reviewer 和 dba 两行

**新增内容：**
```markdown
| reviewer | 代码审查员 | 代码质量审查、安全扫描、最佳实践检查 | 架构师/开发完成后 | 审查报告、改进建议 |
| dba | 数据库管理员 | 数据库设计审查、SQL 优化、数据治理 | 架构师完成后 | DBA 审查报告、优化建议 |
```

### 5.3 validate.sh 残留数字检查（F03）

**方案：** 新增第 10 项检查，使用 grep 扫描旧数字

**检查逻辑：**
```bash
# 第 10 项：Agent 数量残留检查
echo "=== 检查 10: Agent 数量残留 ==="
exclude_patterns="--exclude=CHANGELOG.md --exclude-dir=archive"
old_numbers=$(grep -rn $exclude_patterns -E "(12|13)\s*(个|位)\s*(Agent|角色|agent)" docs/ agents/ .claude/agents/ .cursor/agents/ || true)
if [ -n "$old_numbers" ]; then
    echo "❌ 发现旧 Agent 数量引用："
    echo "$old_numbers"
    exit 1
fi
echo "✅ 无旧 Agent 数量残留"
```

### 5.4 docs/ 过程文档归档（F05）

**方案：** 创建 docs/archive/，移动 v1.8 及之前的过程文档

**归档规则：**
- 文件名匹配：`ITER-*`、`SCOUT-*`、`FEEDBACK-*`、`ARCH-*`、`DEV-*`、`QA-*`、`QG-*`、`MKT-*`、`PRD-*`、`ROLE-RUN-LOG-*`
- 版本判断：根据文件内容中的版本号或日期判断
- 保留：最新一轮过程文档（SCOUT-20260506、FEEDBACK-20260506、MKT-20260506、PRD-20260506）

### 5.5 启动配置降级方案（F06）

**方案：** 在 SKILL.md 增加降级路径

**降级逻辑：**
1. 检测 AskUserQuestion 工具是否可用
2. 如不可用，输出推荐配置文本 + "请回复 1/2/3 选择"
3. 提供环境变量 `PL_MODEL_STRATEGY=inherit` 跳过交互
