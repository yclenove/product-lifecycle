# Token 效率指南

## 问题

多 Agent 协作时，累积的对话历史会快速填满上下文窗口。每个 Agent 的输入输出都消耗 Token。

## 优化策略

### 1. 分层读取

| 层级 | 内容 | Token 消耗 | 何时使用 |
|------|------|-----------|----------|
| L0 | SKILL.md 标题 + 模式选择 | ~200 | 每次必读 |
| L1 | WORKFLOW_PLAN.md 摘要 | ~500 | 每个 Agent 启动时 |
| L2 | 相关文档的具体章节 | ~1000-2000 | 需要详细信息时 |
| L3 | 完整文档 | ~3000-5000 | 极少需要 |

### 2. 摘要传递

Agent 间传递摘要而非全文：

```
Agent A 输出：docs/iterations/current/market/MKT-001.md（3000 字）
  → 生成摘要（300 字）写入 WORKFLOW_PLAN.md
Agent B 输入：只读 WORKFLOW_PLAN.md 中的摘要（300 字）
  → 按需读取 docs/iterations/current/market/MKT-001.md 的相关章节
```

### 3. 输出预算

| Agent | 输出预算 | Token 估算 |
|-------|----------|-----------|
| orchestrator | 3000 字 | ~4000 token |
| architect | 3000 字 | ~4000 token |
| market-analyst | 2000 字 | ~2700 token |
| product-manager | 2500 字 | ~3300 token |
| developer | 1500 字 | ~2000 token |
| qa-manager | 1500 字 | ~2000 token |
| 其他 | 1500-2000 字 | ~2000-2700 token |

### 4. 一次性 vs 增量

| 场景 | 策略 | Token 节省 |
|------|------|-----------|
| 首次构建 | 完整读取 | 0% |
| 迭代改进 | 只读 diff | 60-70% |
| Bug 修复 | 只读相关文件 | 80% |
| 文档更新 | 只读目标文档 | 90% |

### 5. 模型选择与成本

| 模型 | 每 1M token 成本 | 适用场景 |
|------|-----------------|----------|
| 继承用户当前模型 | 常规定价 | 常规任务（开发、测试、文档、审查） |
| 继承用户当前模型 | 高级定价 | 复杂推理（架构、编排） |

**12 Agent 全流程估算：** 约 30,000-50,000 input token + 15,000-25,000 output token
**使用三级模型策略可降低约 30-40% 成本。**
