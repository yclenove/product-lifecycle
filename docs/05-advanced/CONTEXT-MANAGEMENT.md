# 上下文管理指南

> 多 Agent 协作时的上下文窗口管理策略与最佳实践。

## 1. 问题描述

### 1.1 上下文窗口溢出

在多 Agent 协作场景中，每个 Agent 需要读取大量前置文档：

- 编排总监输出的 WORKFLOW_PLAN.md（可能数千字）
- 市场分析师的市场分析报告
- 产品经理的 PRD
- 架构师的技术设计文档
- 历史迭代的变更记录

当这些文档累积到一定程度，会导致：

- **上下文窗口溢出**：超出模型的 token 限制
- **信息丢失**：早期关键信息被截断
- **响应质量下降**：模型在长上下文中表现退化
- **成本增加**：token 消耗线性增长

### 1.2 信息冗余

Agent 间传递完整文档会导致：

- 重复传递已知信息
- 关键信息淹没在细节中
- 后续 Agent 难以快速定位核心内容

## 2. 摘要传递机制

### 2.1 核心原则

**传递关键信息，而非完整历史**

每个 Agent 完成任务后，应生成结构化摘要供下游 Agent 使用，而非传递完整输出。

### 2.2 摘要模板

```markdown
## [Agent 名称] 摘要（供下游使用）

### 关键决策
- 决策 1：[原因]
- 决策 2：[原因]

### 核心产出
- [产出物 1]：[一句话描述]
- [产出物 2]：[一句话描述]

### 对下游的约束
- [约束 1]
- [约束 2]

### 待解决问题
- [问题 1]：[影响范围]
```

### 2.3 WORKFLOW_PLAN.md 中的摘要区

在 WORKFLOW_PLAN.md 中维护每个 Agent 的最新摘要：

```markdown
## Agent 产出摘要

### 市场分析师摘要（更新于 YYYY-MM-DD）
- 目标用户：[画像关键词]
- 核心竞品：[竞品名称]
- 市场机会：[一句话]

### 产品经理摘要（更新于 YYYY-MM-DD）
- 核心功能：[功能列表]
- 验收标准：[关键标准]
- 优先级：P0/P1/P2

### 架构师摘要（更新于 YYYY-MM-DD）
- 技术栈：[关键技术选型]
- 核心模块：[模块列表]
- 风险点：[已知风险]
```

## 3. 上下文预算

### 3.1 预算概念

为每个 Agent 的输入/输出设定 token 预算，防止上下文膨胀。

| Agent | 输入预算 | 输出预算 | 说明 |
|-------|---------|---------|------|
| 编排总监 | 8K | 4K | 框架性输出，无需详细 |
| 市场分析师 | 12K | 6K | 需要详细分析 |
| 产品经理 | 12K | 8K | PRD 需要详细 |
| 架构师 | 16K | 8K | 技术设计需要细节 |
| 开发工程师 | 16K | 12K | 代码实现需要空间 |
| 测试经理 | 12K | 6K | 测试用例可结构化 |
| 运维工程师 | 12K | 6K | 配置文件较固定 |
| 技术文档师 | 16K | 8K | 需要参考代码 |
| 质量门禁 | 16K | 4K | 审查结果简洁 |
| 反馈分析师 | 12K | 6K | 分析报告 |
| 迭代规划师 | 16K | 6K | 计划文档 |
| 需求侦察兵 | 12K | 6K | 侦察报告 |

### 3.2 预算控制策略

**输入控制：**
- 优先读取摘要，按需读取原文
- 使用 `grep` 定位关键段落，避免读取全文
- 限制历史迭代文档读取数量（最多 2 个）

**输出控制：**
- 使用模板约束输出格式
- 关键信息前置，细节后置
- 长代码块使用折叠标记

### 3.3 Prompt 片段示例

```markdown
## 输出约束

- 总长度控制在 3000 字以内
- 使用表格替代长段落
- 代码示例不超过 20 行
- 参考资料使用链接，不内联全文
```

### 4.2 交接检查清单

每个 Agent 启动前，检查：

1. **必读文件**：WORKFLOW_PLAN.md 中的项目状态快照
2. **前置产出**：直接上游 Agent 的摘要
3. **约束条件**：从 WORKFLOW_PLAN.md 复制的质量门禁
4. **历史上下文**：最近 1-2 个迭代的关键变更

### 4.3 交接 Prompt 片段

```markdown
## 启动前检查

在开始任务前，你必须：

1. 读取 WORKFLOW_PLAN.md 中的「项目状态快照」
2. 读取 [上游 Agent] 的摘要（WORKFLOW_PLAN.md → Agent 产出摘要）
3. 确认你的任务在「下游 Agent 启动条件」中已满足
4. 如有疑问，向编排总监确认

## 输出要求

完成任务后，你必须：

1. 生成结构化摘要（参考「摘要模板」）
2. 更新 WORKFLOW_PLAN.md 中的项目状态快照
3. 更新「下游 Agent 启动条件」
```

## 5. 最佳实践

### 5.1 分层读取策略

```markdown
## 读取策略

### 第一层：状态快照（必读）
读取 WORKFLOW_PLAN.md → 项目状态快照

### 第二层：上游摘要（必读）
读取 WORKFLOW_PLAN.md → Agent 产出摘要 → [你的直接上游]

### 第三层：详细文档（按需）
- 如果摘要中有「详见 [文档]」，读取对应段落
- 使用 grep 定位关键词，只读相关段落
- 限制：最多读取 2 个详细文档

### 第四层：历史迭代（极少需要）
- 仅当需要了解历史决策原因时
- 限制：最多读取 1 个历史迭代
```

### 5.2 输出压缩技巧

```markdown
## 输出压缩

### 使用表格替代段落
❌ 错误：
"我们的目标用户是 25-35 岁的年轻专业人士，他们通常在一线城市工作，
使用移动设备为主，注重效率..."

✅ 正确：
| 维度 | 描述 |
|------|------|
| 年龄 | 25-35 岁 |
| 职业 | 一线城专业人士 |
| 设备 | 移动优先 |
| 核心诉求 | 效率 |

### 使用引用块标记关键信息
> **关键决策**：选择 PostgreSQL，因为需要 JSON 支持和复杂查询。

### 代码示例精简
只展示关键代码，省略样板代码：
```python
# 核心逻辑（省略 import 和配置）
def process_order(order: Order) -> Result:
    # ... 关键实现
```
```

### 5.3 紧急情况处理

当上下文即将溢出时：

```markdown
## 紧急压缩策略

如果上下文接近限制（>80%），执行：

1. **删除已完成任务的详细输出**，只保留摘要
2. **压缩代码示例**，只保留函数签名和关键逻辑
3. **合并相似章节**，使用表格替代多个段落
4. **移除注释和说明**，只保留核心内容

优先级：保留 > 当前任务上下文 > 历史上下文 > 格式美化
```

### 5.4 Agent Prompt 中的上下文管理指令

在每个 Agent 的 prompt 中加入以下指令：

```markdown
## 上下文管理

### 输入管理
- 优先读取摘要，按需读取原文
- 如果文档超过 5000 字，只读取与你任务相关的段落
- 使用 grep 定位关键词

### 输出管理
- 总长度控制在 [预算] 字以内
- 使用表格和列表，避免长段落
- 代码示例不超过 20 行
- 关键信息前置

### 状态更新
- 完成后更新 WORKFLOW_PLAN.md 的项目状态快照
- 生成结构化摘要供下游使用
- 标记已解决的问题和新发现的问题
```

## 6. 工具支持

### 6.1 Claude Code 特性利用

- **Prompt Caching**：重复读取的文件自动缓存
- **上下文压缩**：长对话自动压缩历史消息
- **文件搜索**：使用 Grep 定位而非全文读取

### 6.2 推荐工作流

```bash
# 1. 先读状态快照
Read WORKFLOW_PLAN.md

# 2. 按需定位关键信息
Grep "关键决策" docs/

# 3. 只读相关段落
Read docs/PRD-001.md --offset 100 --limit 50

# 4. 输出时使用结构化格式
# 参考模板输出，避免自由文本
```

## 8. 实战案例

### 案例 1：12 Agent 协作的上下文管理

**场景：** 完整的产品生命周期（模式 A）

**策略：**
- 编排总监：输出 WORKFLOW_PLAN.md（~500 字），作为后续 Agent 的唯一上下文入口
- 市场分析师：输出摘要（~300 字）到 WORKFLOW_PLAN.md，全文写入 docs/MKT-xxx.md
- 产品经理：只读市场分析师的摘要，不读全文
- 架构师：只读 PRD 的功能清单和验收标准，不读用户画像

**效果：** 总 token 消耗降低 40%

### 案例 2：迭代场景的上下文压缩

**场景：** 持续迭代（模式 B），已进行到第 5 轮

**策略：**
- 每轮只传递增量信息（与上轮的 diff）
- 历史迭代的详细信息归档到 docs/，不进入当前上下文
- WORKFLOW_PLAN.md 只保留当前轮次的状态

## 9. Agent 间信息交接

### 9.1 交接清单

每个 Agent 完成后，必须：

1. **更新 WORKFLOW_PLAN.md**：写入摘要（≤200 字）
2. **保存详细产出**：写入 docs/xxx.md
3. **标注依赖**：在摘要中说明哪些下游 Agent 需要读取
4. **标注状态**：完成/部分完成/阻塞

**交接模板：**

```markdown
## [Agent 名称] 交接记录

### 完成状态
- [x] 更新 WORKFLOW_PLAN.md 摘要
- [x] 保存详细产出到 docs/xxx.md
- [x] 标注下游依赖
- [x] 标注状态

### 产出物清单
| 文件 | 路径 | 状态 |
|------|------|------|
| 市场分析报告 | docs/MKT-001-*.md | 完成 |
| 竞品对比表 | docs/MKT-001-*.md#竞品 | 完成 |

### 下游依赖
- 产品经理：需要读取目标用户画像和竞品分析
- 编排总监：需要读取市场机会评估
```

### 9.2 下游 Agent 读取规则

| 场景 | 读取策略 |
|------|----------|
| 首次读取 | 先读 WORKFLOW_PLAN.md 中的摘要 |
| 需要细节 | 按需读取 docs/xxx.md 的相关章节 |
| 上下文紧张 | 只读摘要，不读全文 |
| 需要验证 | 读取原文中的数据/证据部分 |

**读取优先级：**

1. **第一层：状态快照（必读）**
   - 读取 WORKFLOW_PLAN.md → 项目状态快照

2. **第二层：上游摘要（必读）**
   - 读取 WORKFLOW_PLAN.md → Agent 产出摘要 → [你的直接上游]

3. **第三层：详细文档（按需）**
   - 如果摘要中有「详见 [文档]」，读取对应段落
   - 使用 grep 定位关键词，只读相关段落
   - 限制：最多读取 2 个详细文档

4. **第四层：历史迭代（极少需要）**
   - 仅当需要了解历史决策原因时
   - 限制：最多读取 1 个历史迭代

### 9.3 信息压缩策略

| 10000 字 | 800 字 | 只保留摘要和引用路径 |
