## 痛点分组与证据

### 1. 文档一致性与信任问题（P0）

- `README.md`：开头和角色表已写 14 个 Agent，但 Cursor 小节仍写 `.cursor/agents/` 为 12 角色，目录树写 `.claude/agents/` 为 13 角色。
- `docs/QUICK-START.md`：30 秒理解仍写 12 Agent，最小可用集和 FAQ 仍写 13 个 Agent，完整项目也写全部 13 个。
- `docs/DECISION-TREE.md`：企业级、大版本升级、完整项目仍写全部 13 个。
- `docs/SKILL-ASSETS.md`：标题为「13 Agent 角色与产出」，表内实际有 14 行；模型策略仍写「其余 11 个 Agent」。
- `SKILL.md`：主体已写 14 个 Agent，但 frontmatter 中文触发仍写「13个Agent协作」，资源索引文案仍写「12 角色产出表」。

用户影响：新用户会把数字不一致解读为版本失控，降低对「流程技能包」的信任。

### 2. Windows 首次上手体验（P1）

- v2.6.0 已新增 `scripts/validate.ps1`、`scripts/sync-agents.ps1`、`scripts/iterate.ps1`。
- `docs/SKILL-CURSOR.md` 已给出 PowerShell 安装 Cursor Subagent 的命令。
- 但 `docs/QUICK-START.md` 仍没有「Windows 复制即跑」的自检路径，且 `scripts/validate.ps1` 当前仍按 13 个 Agent 校验。

用户影响：国内 Windows 用户很可能先读 QUICK-START，却看不到最顺手的 PowerShell 自检方式。

### 3. 多工具路径认知负担（P1）

- README 同时面向 Claude Code、Cursor、OpenCode / Codex 和通用方法。
- Cursor 需要理解全局技能目录、业务工作区、`PRODUCT_LIFECYCLE_ROOT`、`.cursor/agents/` 薄封装和重载窗口。
- `.cursor/agents/README.md` 仍写「共 12 个角色」，进一步放大混淆。

用户影响：产品定位是工具无关，但安装路径越多，越需要每种工具的一页式成功路径和成功标志。

### 4. 自动化门禁缺口（P1）

- `validate.sh` 已验证 `.claude/agents/` 数量为 14、上下文管理覆盖 14/14、同步 14/14。
- `test-agents.sh`、`test-templates.sh` 可证明 prompt 与模板结构健康。
- 但旧角色数字残留不在门禁内；`validate.ps1` 与 `validate.sh` 数量规则已分叉。

用户影响：维护者看到「全部通过」后仍可能发布带明显文档漂移的版本。

### 5. 新增企业级能力缺少展示（P2）

- v2.6.0 新增 DBA Agent、MySQL MCP / 多数据库 MCP 集成说明、QA UI 自动化章节。
- README 角色表已列出 DBA，但 examples 仍主要是 CloudFlow、SaaS、CLI、Microservice，未把 DBA + MCP 的闭环价值讲清楚。

用户影响：企业用户能看到能力点，但缺少「为什么要为它引入完整生命周期流程」的实证样例。

## Top 5 高优先级问题

1. **角色数量漂移（P0）**
   - 用户原话模拟：「README 说 14 个，快速入门说 12/13 个，我该信哪个？」
   - 影响：阻断首次信任建立，影响全部用户。
   - 修复方向：统一 README、SKILL、QUICK-START、DECISION-TREE、SKILL-ASSETS、DOC-MAP、Cursor README 的当前角色数。

2. **SKILL-ASSETS 作为入口索引不可信（P0）**
   - 用户原话模拟：「表里明明 14 行，标题还是 13 Agent，模型策略也对不上。」
   - 影响：根 SKILL 引用该文件，影响所有工具用户查角色和模型策略。
   - 修复方向：标题、表述、模型策略同步为 14，并补充 DBA 的模型归类。

3. **PowerShell 验证脚本落后于 bash（P0）**
   - 用户原话模拟：「Windows 版验证失败，但 bash 版通过，是不是我安装错了？」
   - 影响：直接打击 Windows 用户的一键验证信心。
   - 修复方向：`validate.ps1` 全部数量检查改为 14/14，并与 `validate.sh` 保持同一检查项含义。

4. **QUICK-START 未承接 Windows 机会（P1）**
   - 用户原话模拟：「我是 Windows 用户，最快验证安装成功应该跑哪条命令？」
   - 影响：降低新手转化率。
   - 修复方向：增加 Windows PowerShell 5 分钟体验、自检命令、常见执行策略提示。

5. **验证脚本缺文档漂移门禁（P1）**
   - 用户原话模拟：「CI 绿了，但文档还是旧的。」
   - 影响：维护者重复踩坑，版本扩容时风险上升。
   - 修复方向：新增权威文档残留扫描，范围限定为 README、SKILL、docs/SKILL-*.md、QUICK-START、DECISION-TREE、SKILL-ASSETS、DOC-MAP，排除历史报告和 CHANGELOG。
