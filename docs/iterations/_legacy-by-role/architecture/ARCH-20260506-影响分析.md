## 四、F03：validate.sh 残留数字检查

### 4.1 当前 validate.sh 结构

现有 **9 项检查**，编号 1-9：

| 检查项 | 内容 | 类型 |
|--------|------|------|
| 1 | SKILL.md frontmatter 存在 | 结构 |
| 2 | .claude/agents/ 数量 = 14 | 数量 |
| 3 | PRODUCT_PLAN 残留 | 内容 |
| 4 | trends 2025 残留 | 内容 |
| 5 | 上下文管理覆盖 = 14 | 内容 |
| 6 | Agent 必需章节（任务/输出/质量门禁/上下文管理） | 结构 |
| 7 | 模板元数据 | 结构 |
| 8 | Agent 行数范围（80-400） | 结构 |
| 9 | .claude/agents/ 与 agents/ 同步 | 同步 |

### 4.2 新增检查 10 的融入方案

建议在检查 9 之后、汇总之前插入检查 10。技术要点：

1. **grep 模式**：`(12|13)\s*(个|位)\s*(Agent|角色)` 及 `11\s*个\s*Agent`
2. **扫描范围**：`SKILL.md`、`README.md`、`docs/QUICK-START.md`、`docs/DECISION-TREE.md`、`docs/SKILL-ASSETS.md`、`docs/SKILL-CURSOR.md`、`docs/DOC-MAP.md`、`docs/FAQ.md`、`.cursor/agents/README.md`、`agents/*.md`、`.claude/agents/*.md`
3. **排除规则**：`CHANGELOG.md`、`docs/archive/`、`docs/BACKLOG-*`、`docs/FEEDBACK-*`（非 20260506）、`docs/SCOUT-*`（非 20260506）、`docs/ITER-*`（非 20260506）
4. **同时扫描 `11 个 Agent`**：SKILL-ASSETS.md 第 112 行有 `其余 11 个 Agent`，需纳入

### 4.3 风险点

- **误报风险**：迭代计划的 grep 模式 `(12|13)\s*(个|位)\s*(Agent|角色)` 无法捕获 `11 个 Agent` 这种变体，也无法捕获 `12 Agent`（无量词）的写法（如 QUICK-START.md 第 5 行）
- **建议扩展模式**：`(1[1-3])\s*(个|位)?\s*(Agent|角色)` 以覆盖无量词场景

## 十一、技术建议

### 11.1 对迭代计划的修正建议

1. **F01 范围修正**：将文件清单从 5 个扩展到 8 个，新增 `docs/QUICK-START.md`、`docs/DECISION-TREE.md`、`docs/FAQ.md`、`docs/SKILL-ASSETS.md`、`.cursor/agents/README.md`
2. **validate.ps1 纳入 F01**：3 处硬编码 `13` 需同步修改
3. **F03 grep 模式扩展**：增加 `11\s*(个|位)?\s*Agent` 模式，覆盖 SKILL-ASSETS.md 的 `其余 11 个 Agent`
4. **F03 扫描范围扩展**：增加 `docs/QUICK-START.md`、`docs/DECISION-TREE.md`、`docs/FAQ.md`、`docs/SKILL-ASSETS.md`、`.cursor/agents/README.md`

### 11.2 工程实践建议

1. **F01 执行方式**：建议使用精确的逐文件替换而非全局 sed，避免误改 CHANGELOG 等历史记录
2. **F05 执行方式**：使用 `git mv` 保留历史；归档前先创建 `docs/archive/` 并提交一次，再批量移动
3. **F03 验证方式**：新检查 10 添加后，应先故意注入一处旧数字验证检查能失败，再修正验证能通过
4. **CI 兼容性**：validate.sh 新增检查项无需修改 CI 配置，脚本自动包含；但需确认 CI 环境的 grep 支持 `-E` 扩展正则

### 11.3 长期改进建议

1. **消除硬编码数字**：validate.sh 和 validate.ps1 应从 `agents/` 目录文件数动态推导期望值，而非硬编码 `14`
2. **统一跨平台检查逻辑**：validate.sh 和 validate.ps1 的检查项应保持完全一致，建议维护一份检查项清单作为单一数据源

## 十二、结论

v2.7.0 迭代计划整体可行，但存在 **3 个需要在执行前修正的偏差**：

1. **F01 文件清单不完整**（4 个文件遗漏、validate.ps1 遗漏）

修正上述偏差后，P0 任务可在 2 人天内完成，P1 任务可在 3 人天内完成，整体迭代目标可达成。
