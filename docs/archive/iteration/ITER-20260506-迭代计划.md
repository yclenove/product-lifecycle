### F03: validate.sh 残留数字检查（P0，0.5 天）

**目标：** 新增第 10 项检查，自动扫描旧 Agent 数量引用。

| 任务 | 执行步骤 | 预计耗时 |
|------|----------|----------|

| T03.4 | 运行验证，确认新检查项正常工作 | 30 分钟 |

**检查逻辑：**

```bash
# 第 10 项：Agent 数量残留检查
echo "=== 检查 10: Agent 数量残留 ==="
exclude_patterns="--exclude=CHANGELOG.md --exclude-dir=archive --exclude-dir=docs/archive"
old_numbers=$(grep -rn $exclude_patterns -E "(12|13)\s*(个|位)\s*(Agent|角色|agent)" docs/ agents/ .claude/agents/ .cursor/agents/ 2>/dev/null || true)
if [ -n "$old_numbers" ]; then
    echo "❌ 发现旧 Agent 数量引用："
    echo "$old_numbers"
    errors=$((errors+1))
else
    echo "✅ 无旧 Agent 数量残留"
fi
```

**排除范围：**
- `CHANGELOG.md`（历史记录保留原样）
- `docs/archive/`（归档内容不做修改）

## 六、回滚方案

### 6.1 整体回滚

如果 v2.7.0 引入严重问题，可通过以下步骤回滚到 v2.6.0：

```bash
# 1. 回退到 v2.6.0 tag
git checkout v2.6.0

# 2. 创建回滚分支
git checkout -b hotfix/rollback-v2.7.0

# 3. 强制推送（如果需要）
git push origin hotfix/rollback-v2.7.0 --force

# 4. 通知用户
echo "已回滚到 v2.6.0，请重新安装"
```

### 6.2 单功能回滚

| 功能 | 回滚方式 | 风险 |
|------|----------|------|
| F01 (数字替换) | `git revert` 对应 commit | 低：纯文本替换 |
| F02 (Subagent 表) | `git revert` 对应 commit | 低：新增行 |
| F03 (validate.sh) | `git revert` 对应 commit | 低：新增检查项 |

如果在发布后发现问题：

1. **P0 问题（阻断使用）**：立即创建 hotfix 分支修复，发布 v2.7.1

3. **P2 问题（可接受）**：记录到 Backlog，按优先级排期
