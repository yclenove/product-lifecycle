- **建议处理方式：**
  1. 在 SKILL-CLAUDE-CODE.md 中增加 Hooks 配置示例
  2. 提供 `.claude/settings.json` 模板（含 PreToolUse/PostToolUse hooks）
  3. 区分"可自动化门禁"和"需人工审查门禁"

### 4.11 FB045: validate.sh 仅检查 .claude/agents/ 文件存在性

- **描述：** `scripts/validate.sh` 第 9 项检查（v2.5.0 新增）仅验证 `.claude/agents/` 中是否有与 `agents/` 对应的文件，不检查内容一致性（如必需章节、行数范围）。如果 `.claude/agents/` 的派生文件内容不完整，CI 门禁无法发现。
- **来源：** 内部审查 scripts/validate.sh
- **频次：** 中（每次 CI 运行都暴露此盲区）
- **影响面：** 部分（影响 CI 质量门禁的可靠性）
- **严重度：** 一般
- **优先级分：** 4
- **建议处理方式：**
  1. 为 `.claude/agents/` 新增行数范围检查（与 agents/ 相同的 80-400 行标准）
  2. 新增必需章节检查（任务/输出/质量门禁/上下文管理）
  3. 新增 `.cursor/agents/` 同步检查

### 4.12 FB046: 启动配置脚本硬编码 Agent 数量

- **描述：** SKILL.md 第 69/76/93 行的启动配置脚本硬编码"其余 12 个"。每次新增 Agent 时需手动更新此数字，容易遗漏（本次 v2.6.0 新增 DBA 后此处未更新，但 14-2=12 恰好正确）。
- **来源：** 内部审查 SKILL.md
- **频次：** 低（仅新增 Agent 时触发）
- **影响面：** 局部
- **严重度：** 建议
- **优先级分：** 2
- **建议处理方式：** 将硬编码数字改为动态计算（如脚本中 `count=$(ls agents/*.md | wc -l)`）或在新增 Agent 的 checklist 中包含此检查项
