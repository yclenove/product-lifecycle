## 3. Top 5 高优先级问题

### 3.1 FB001: 多 Agent 上下文窗口溢出

- **描述：** 当多个 Agent 协作时，累积的对话历史、工具输出和中间推理会快速填满 200K token 上下文窗口。关键信息被截断，导致 Agent 决策质量下降。
- **来源：** 社区讨论（GitHub Issues、Reddit r/ClaudeAI）、竞品（Cursor）用户反馈
- **频次：** 高（多 Agent 场景必现）
- **影响面：** 全局（影响所有模式 A 和模式 B 的执行）
- **优先级分：** 9（频次3 × 影响面3）
- **建议处理方式：**
  1. 实现 Agent 间摘要传递机制（hierarchical summarization）
  2. 在 SKILL.md 中增加上下文管理最佳实践
  3. 考虑引入"上下文预算"概念，限制每个 Agent 的输出长度

### 3.2 FB006: 缺少渐进式采用路径

- **描述：** 当前框架要求理解 12 个 Agent 的完整体系才能使用，学习曲线陡峭。用户希望从小规模开始（如只用 3-4 个核心 Agent），逐步扩展。
- **来源：** 竞品分析（Cursor rules 的简单性优势）、社区讨论
- **频次：** 中
- **影响面：** 全局（影响新用户采纳率）
- **优先级分：** 6（频次2 × 影响面3）
- **建议处理方式：**
  1. 定义"核心 Agent 子集"（编排总监 + 开发 + 测试 + 质量门禁）
  2. 提供"精简模式"启动指引
  3. 在 README 中增加"5 分钟快速上手"章节

### 3.3 FB002: Agent 切换时背景重复说明

- **描述：** 切换 Agent 时需要重新说明项目背景、技术栈、当前进度等信息，浪费 token 且容易遗漏关键上下文。
- **来源：** 竞品反馈（Cursor rules 的持久化优势）、最佳实践文献
- **频次：** 高
- **影响面：** 全局
- **优先级分：** 6（频次3 × 影响面2）
- **建议处理方式：**
  1. 强化 `.claude/agents/` 的动态上下文注入（已在 v1.4 部分实现）
  2. 在 WORKFLOW_PLAN.md 中维护"项目状态快照"
  3. 每个 Agent 启动时自动读取项目状态文件

### 3.4 FB003: 文档模板过于刚性

- **描述：** 模板设计偏向大型企业项目，小型项目或 MVP 场景下很多章节显得冗余。
- **来源：** 社区讨论（V2EX、Reddit）
- **频次：** 中
- **影响面：** 部分（主要影响小型项目用户）
- **优先级分：** 4（频次2 × 影响面2）
- **建议处理方式：**
  1. 为每个模板增加"精简版"（标记必填 vs 可选章节）
  2. 在模板中增加"项目规模适配"指引
  3. 提供不同规模的示例（小型/中型/大型）

### 3.5 FB004: 缺少 Agent 执行状态可视化

- **描述：** 用户无法直观看到当前工作流进展、哪个 Agent 正在执行、整体完成度。
- **来源：** 社区讨论、竞品对比（Cursor 的 UI 优势）
- **频次：** 中
- **影响面：** 全局
- **优先级分：** 4（频次2 × 影响面2）
- **建议处理方式：**
  1. 在 WORKFLOW_PLAN.md 中增加进度追踪表
  2. 编排总监定期输出"状态摘要"
  3. 考虑使用 TodoWrite 工具追踪 Agent 执行状态

## 4. 竞品对比差距


| 维度    | product-lifecycle    | Cursor rules  | Claude Code CLAUDE.md | 差距分析                |
| ----- | -------------------- | ------------- | --------------------- | ------------------- |
| 上下文管理 | Agent 独立，无跨 Agent 摘要 | 持久化 rules 文件  | 自动加载 CLAUDE.md        | **落后**：缺少跨会话上下文传递   |
| 学习曲线  | 陡峭（12 Agent 体系）      | 平缓（单文件 rules） | 平缓（单文件）               | **落后**：缺少渐进式采用路径    |
| 工具集成  | 通用（支持多工具）            | 专属 Cursor     | 专属 Claude Code        | **领先**：工具无关设计       |
| 流程完整性 | 端到端闭环                | 无流程定义         | 无流程定义                 | **领先**：完整生命周期管理     |
| 可视化   | 文档为主                 | IDE 集成        | CLI 输出                | **落后**：缺少进度可视化      |
| 自动化程度 | 高（12 Agent 协作）       | 低（手动触发）       | 中（skill 触发）           | **领先**：多 Agent 自动协调 |


**关键差距：**

1. **上下文管理**是最突出的短板，直接影响多 Agent 协作质量
2. **学习曲线**阻碍新用户采纳，需要"快速上手"路径
3. **可视化**在 CLI 环境下天然劣势，但可通过文档弥补
