## 建议优先级

### P0：立即行动

1. 统一所有权威入口的 Agent 数量与角色清单：`README.md`、`SKILL.md`、`docs/QUICK-START.md`、`docs/DECISION-TREE.md`、`docs/SKILL-ASSETS.md`。
2. 在验证脚本中加入「权威文档角色数一致性」检查，避免 12/13/14 反复漂移。
3. 明确 `.claude/worktrees/` 的忽略或清理策略，避免污染用户对仓库状态的判断。

### P1：下个迭代

1. 增加安装后自检指南：`validate`、`test-agents`、`test-templates`、`iterate --check`。
2. 增加 Windows PowerShell 快速路径，降低国内 Windows 用户上手成本。
3. 为 DBA + UI 自动化 MCP 能力补一个完整示例，证明企业级场景价值。

### P2：持续关注

1. 跟踪 Claude Code Subagents/Agent teams、Cursor Agents、GitHub Copilot coding agent 的配置能力变化。
2. 评估是否将本项目从「技能包」进一步包装为「可安装多 Agent 工作流套件」。
3. 定期清理或归档历史过程稿，保留可追溯性但降低新用户认知负担。

## 下一步输入给反馈分析师的要点

1. 用户最可能遇到的痛点不是功能缺失，而是「文档入口太多、版本数字不一致」。
2. 需要收集新用户首次安装后的卡点：模型配置、技能路径、Cursor Subagent 安装、PowerShell 执行策略。
3. 反馈分类建议新增「文档一致性」与「安装自检」两个标签。
4. open issues 当前为 0，不代表无用户痛点，应结合 README、历史反馈报告和安装路径做主动反馈模拟。

## 下一步输入给市场分析师的要点

1. 竞品方向正在强化「官方 Agent 能力」和「异步编码任务」，本项目应强调端到端产品流程和跨工具可迁移性。
2. Claude Code Subagent 官方能力与本项目高度相关，可作为市场定位中的可信背书，但不要绑定单一工具。
3. Cursor、GitHub Copilot 等更偏工具内原生体验，本项目差异化应放在可审计文档产出、角色分工和质量闭环。
4. 市场分析需要重点比较：原生 Agent 工具、单一 CLAUDE.md/Rules 工作流、MCP 工具集成型方案。
