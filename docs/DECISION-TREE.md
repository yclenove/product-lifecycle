# Agent 选择决策树

## 项目类型判断

```
你有什么项目？
├── 全新项目（无代码）
│   ├── 简单原型 → 编排总监 + 开发（2 个）
│   ├── 正式项目 → 核心 4 个 + 架构师（5 个）
│   └── 企业级 → 全部 12 个
├── 已有项目（有代码）
│   ├── 小修小补 → 编排总监 + 开发 + 测试（3 个）
│   ├── 新功能 → 核心 4 个 + 架构师（5 个）
│   └── 大版本升级 → 全部 12 个（模式 B）
└── 持续维护
    ├── 只修 bug → 编排总监 + 开发 + 测试 + 质量门禁（4 个）
    └── 功能迭代 → 全部 12 个（模式 B）
```

## Agent 组合推荐

| 场景 | Agent 组合 | 预计耗时 |
|------|-----------|----------|
| 快速原型 | 编排 + 开发 | 30 分钟 |
| MVP | 编排 + 开发 + 测试 | 1 小时 |
| 正式发布 | 核心 4 个 | 2 小时 |
| 完整项目 | 全部 12 个 | 4-8 小时 |
| 持续迭代 | 侦察 + 反馈 + 规划 + 核心 4 个 | 每轮 1-2 小时 |

## 按场景选择

### 场景 1：我有个想法，想快速验证

**推荐组合：** 编排总监 + 开发工程师

**流程：**
1. 编排总监分析需求，制定最简计划
2. 开发工程师快速实现原型
3. 30 分钟内看到可运行的结果

**适合：** 个人项目、hackathon、概念验证

### 场景 2：我要做一个能用的产品

**推荐组合：** 核心 4 个（编排 + 开发 + 测试 + 质量门禁）

**流程：**
1. 编排总监制定工作流
2. 开发工程师实现功能
3. 测试经理验证质量
4. 质量门禁审查代码

**适合：** MVP、内部工具、小型项目

### 场景 3：我要做一个完整的产品

**推荐组合：** 核心 4 个 + 市场分析师 + 产品经理 + 架构师

**流程：**
1. 市场分析师调研竞品和用户
2. 产品经理定义 PRD
3. 架构师设计技术方案
4. 开发 + 测试 + 质量门禁实现

**适合：** 商业产品、正式项目、团队协作

### 场景 4：我要做一个企业级系统

**推荐组合：** 全部 12 个 Agent

**流程：**
1. 完整的市场调研和用户分析
2. 详细的 PRD 和架构设计
3. 专业的开发、测试、运维
4. 完整的文档和持续迭代

**适合：** 企业级系统、长期项目、大型团队

### 场景 5：我要持续迭代已有产品

**推荐组合：** 侦察 + 反馈 + 规划 + 核心 4 个

**流程：**
1. 需求侦察兵扫描市场动态
2. 反馈分析师收集用户反馈
3. 迭代规划师制定迭代计划
4. 核心 4 个执行开发

**适合：** 已上线产品、持续改进、版本升级

## 常见误区

### 误区 1：小项目也需要 12 个 Agent

**真相：** 4 个核心 Agent 就能覆盖 80% 的场景。只有复杂项目才需要更多。

### 误区 2：必须按顺序启动所有 Agent

**真相：** 编排总监会自动判断需要哪些 Agent，跳过不必要的步骤。

### 误区 3：Agent 太多会很慢

**真相：** 多个 Agent 可以并行执行。编排总监会优化启动顺序，最大化并行度。

### 误区 4：我需要理解每个 Agent 的职责

**真相：** 你只需要告诉编排总监你的目标，它会自动协调其他 Agent。
