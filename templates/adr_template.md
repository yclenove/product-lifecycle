### 示例：ADR-001 选择 JWT 作为认证方案

**背景：** 系统需要支持无状态的用户认证，服务端不存储会话信息，支持多端登录。

**决策：** 采用 JWT（JSON Web Token）作为认证方案，Token 有效期 1 小时，支持 Refresh Token 机制。

**理由：**
| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Session + Cookie | 服务端可控、易撤销 | 有状态、跨域麻烦 | 不采用 |
| JWT | 无状态、跨域友好 | Token 难以主动撤销 | 选定 |
| OAuth 2.0 | 标准化、第三方支持 | 实现复杂、当前无需求 | 后续考虑 |

**正面影响：**
- 服务端无状态，易水平扩展
- 前后端分离友好，支持跨域

**负面影响：**
- Token 一旦签发无法主动撤销，需依赖短有效期
- Payload 明文可读，敏感信息不能放入

</details>
