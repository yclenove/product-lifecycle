# [项目名] 文档编排工作流

> 本文档定义 N 个专业 Agent 的职责边界、产出物、依赖关系与质量标准。

---

## 1. Agent 职责与产出物

### 1.1 市场分析师

| 维度 | 内容 |
|------|------|
| **职责** | 调研竞品、目标市场、用户画像、定价策略 |
| **模板** | `templates/market_template.md` |
| **产出物** | 市场分析报告 |
| **输入依赖** | PRODUCT_PLAN.md、竞品公开资料 |
| **不负责** | 产品需求定义、技术方案选型 |

### 1.2 产品经理

| 维度 | 内容 |
|------|------|
| **职责** | 将市场洞察与项目愿景转化为分阶段的产品需求 |
| **模板** | `templates/product_template.md` |
| **产出物** | PRD（功能列表、用户故事、验收标准） |
| **输入依赖** | 市场分析报告、PRODUCT_PLAN.md |
| **不负责** | 竞品调研、技术实现细节 |

### 1.3 架构师

| 维度 | 内容 |
|------|------|
| **职责** | 将产品需求转化为技术设计 |
| **模板** | `templates/architecture_template.md` |
| **产出物** | 技术设计文档（模块、数据模型、API、部署） |
| **输入依赖** | PRD、PRODUCT_PLAN.md、现有代码 |
| **不负责** | 市场调研、需求优先级排序 |

### 1.4 测试经理

| 维度 | 内容 |
|------|------|
| **职责** | 基于 PRD 与技术设计制定测试策略 |
| **模板** | `templates/qa_template.md` |
| **产出物** | 测试计划（策略、用例、质量门禁） |
| **输入依赖** | PRD、技术设计文档、PRODUCT_PLAN.md NFR |
| **不负责** | 产品需求定义、架构设计 |

---

## 2. 依赖关系

```
Phase A: 编排总监（制定框架）
    ↓
Phase B: 并行启动
    ├── 市场分析师 ──────────────────┐
    ├── 产品经理 ← PRODUCT_PLAN.md ─┤
    ├── 架构师 ← PRD 初稿 ──────────┤
    └── 测试经理 ← PRD + 架构设计 ──┘
```

---

## 3. 文档模板规范

### 3.1 元数据头

```markdown
| 字段 | 值 |
|------|-----|
| 版本 | v0.1（初稿）/ v1.0（定稿） |
| 作者 | Agent 名称或人名 |
| 日期 | YYYY-MM-DD |
| 状态 | 草稿 / 评审中 / 已定稿 / 已废弃 |
| 关联文档 | 文档编号或文件路径 |
```

### 3.2 状态流转

```
草稿 → 评审中 → 已定稿
                → 已废弃
```

### 3.3 章节标记

- `[必填]` — 必须有实质内容
- `[可选]` — 可留空
- `[条件：xxx]` — 满足条件时填写

---

## 4. 质量标准

### 4.1 通用门禁

| 检查项 | 标准 |
|--------|------|
| 元数据完整 | 版本、作者、日期、状态均已填写 |
| 必填章节齐全 | 标注 `[必填]` 的章节有实质内容 |
| 交叉引用有效 | 引用链接可跳转 |
| 术语一致 | 同一概念使用相同名称 |
| 无敏感信息 | 不含密钥、密码、隐私数据 |
| 中文撰写 | 正文中文，技术术语保持英文 |

### 4.2 专项门禁

| Agent | 专项要求 |
|-------|---------|
| 市场分析师 | ≥3 竞品、≥2 用户画像、数据来源标注 |
| 产品经理 | 每功能有验收标准、优先级标注、NFR 对齐 |
| 架构师 | 技术栈对齐、数据模型有 ER、API 有示例 |
| 测试经理 | P0 验收标准全覆盖、环境要求明确、量化门禁 |

---

## 5. 执行指南

### 5.1 启动新阶段

1. 编排总监确认当前 Phase
2. 启动编排 Agent，产出框架和模板
3. 按依赖顺序并行启动 Agent
4. 每个 Agent 完成初稿后提交评审
5. 编排总监组织交叉审查

### 5.2 定稿回流

1. 在私有仓把想法写透
2. 提炼可对外负责的段落
3. 在公开仓改 docs/ 或新增 ADR
4. 公开提交使用中文说明
