## 2. 依赖关系

```
Phase 1: 编排总监（制定框架）
    ↓
Phase 2: 调研与规划
    ├── 市场分析师 ──────────────────┐
    └── 产品经理 ← docs/iterations/current/product/PRD-*.md ─┘
    ↓
Phase 3: 设计与实现
    ├── 架构师 ← PRD 初稿
    ├── 开发工程师 ← PRD + 架构设计
    ├── 测试经理 ← PRD + 架构设计
    ├── 运维工程师 ← 架构设计 + 代码
    └── 技术文档师 ← 代码 + PRD
    ↓
Phase 4: 质量门禁 → 发布 → 反馈 → 下一迭代
```

## 3. 文档模板规范

### 3.1 元数据头

```markdown
| 字段 | 值 |
|------|-----|
| 版本 | v0.1（初稿）/ v1.0（定稿） |
| 作者 | Agent 名称或人名 |
| 日期 | YYYY-MM-DD |
| 状态 | 草稿 / 评审中 / 已定稿 / 已废弃 |
| 关联文档 | 文档编号或文件路径 |
```

### 3.2 状态流转

```
草稿 → 评审中 → 已定稿
                → 已废弃
```

### 3.3 章节标记

- `[必填]` — 必须有实质内容
- `[可选]` — 可留空
- `[条件：xxx]` — 满足条件时填写

## 4. 质量标准

### 4.1 通用门禁

| 检查项 | 标准 |
|--------|------|
| 元数据完整 | 版本、作者、日期、状态均已填写 |
| 必填章节齐全 | 标注 `[必填]` 的章节有实质内容 |
| 交叉引用有效 | 引用链接可跳转 |
| 术语一致 | 同一概念使用相同名称 |
| 无敏感信息 | 不含密钥、密码、隐私数据 |
| 中文撰写 | 正文中文，技术术语保持英文 |

### 4.2 专项门禁

| Agent | 专项要求 |
|-------|---------|
| 编排总监 | 框架完整、模板齐全、依赖关系清晰 |
| 市场分析师 | ≥3 竞品、≥2 用户画像、数据来源标注 |
| 产品经理 | 每功能有验收标准、优先级标注、NFR 对齐 |
| 架构师 | 技术栈对齐、数据模型有 ER、API 有示例 |
| 测试经理 | P0 验收标准全覆盖、环境要求明确、量化门禁 |
| 开发工程师 | 单元测试通过、静态分析无警告、代码 review 通过 |
| 运维工程师 | 容器构建成功、服务启动正常、健康检查通过 |
| 技术文档师 | README 准确、API 文档完整、CHANGELOG 更新 |

## 5. 执行指南

### 5.1 启动新阶段

1. 编排总监确认当前 Phase
2. 启动编排 Agent，产出框架和模板
3. 按依赖顺序并行启动 Agent
4. 每个 Agent 完成初稿后提交评审
5. 编排总监组织交叉审查

### 5.2 定稿回流

1. 在私有仓把想法写透
2. 提炼可对外负责的段落
3. 在公开仓改 docs/ 或新增 ADR
4. 公开提交使用中文说明

## 6. 错误处理与检查点

### 6.1 常见失败与处理

| 情形 | 处理 |
|------|------|
| 上游文档缺失 | 按各 Agent「文档健康检查」规则反推初稿后再继续；在 WORKFLOW_PLAN 中记录补写范围 |
| Agent 输出不满足门禁 | 打回对应角色，附具体检查项；禁止带着「待定」进入下一阶段 |
| 并行 Agent 结论冲突 | 由编排总监合并；冲突点写入 WORKFLOW_PLAN「待决议」并在 PRD 定稿前关闭 |
| 工具/调研不可用 | 市场/产品类角色标注「数据来源受限」并缩小结论范围，不得虚构竞品数据 |

### 6.2 Phase 出口检查（最小集）

| Phase | 检查 |
|-------|------|
| 调研与规划 | PRD 中 P0 项均有验收标准；市场报告标注数据来源 |
| 设计与实现 | 架构设计与 PRD P0 范围对齐；开发分支可构建 |
| 测试 | P0 用例全通过或有已登记豁免 |
| 质量门禁 | QG 报告结论为通过或「有条件通过」且条件已指派责任人 |

### 6.3 回滚与冻结

- **回滚**：若发布后缺陷升级，在 CHANGELOG `[Unreleased]` 记 incident，必要时恢复上一 tag 的文档叙事并开 hotfix 迭代。
- **冻结**：发版前 24h 冻结 WORKFLOW_PLAN 与 PRD 的 P0 文案，仅允许 typo 与链接修复。
